# Examples

Five projects generated by the real CLI, so they show exactly what `fastify-ep` produces. They are
regenerated with `npm run build && npm run examples` and CI fails if they drift from the templates.
Do not edit them by hand. Each one is also installed, checked with `doctor --strict`, typechecked,
tested and built in CI, and the database ones are smoke-tested against PostgreSQL.

Every example was created with `init`, then `generate module orders` and `generate resource users --crud`.

| Example | Preset | Database | Dependencies | Shows |
|---|---|---|---|---|
| [`minimal-api`](minimal-api) | minimal | none | native | The smallest project: error handler, health probes, graceful shutdown, no OpenAPI |
| [`production-api`](production-api) | production | Drizzle | native | Security headers, CORS, rate limiting, a Dockerfile |
| [`drizzle-api`](drizzle-api) | standard | Drizzle | native | CRUD resource on Drizzle, OpenAPI at `/documentation`, database readiness |
| [`prisma-api`](prisma-api) | standard | Prisma | native | The same resource on Prisma |
| [`awilix-api`](awilix-api) | standard | Drizzle | Awilix | Container-based dependency injection with a repository |

## Running one

```sh
cd drizzle-api
cp .env.example .env
docker compose up -d
npm install
npm run db:generate && npm run db:migrate
npm run dev
```

`minimal-api` needs none of the database steps. The `users` repository test runs only when
`TEST_DATABASE_URL` is set; see `docs/database.md`.
